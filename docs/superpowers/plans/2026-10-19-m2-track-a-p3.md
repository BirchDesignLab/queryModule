**Architecture:** No new subsystem. The sweeper (`packages/api/src/dispatch/sweeper.ts`) gains a stop check between sessions and a per-tick skip set; the fatal `close()` in `startup.ts` stops accepting before it waits. The admin query read mounts beside the owner's read in `packages/api/src/queries/route.ts`, sharing one query-string error helper with `audit/routes.ts`. The image config import is an ops command over the existing store (`admin/config/store.ts`, `activate()`), never an automatic merge at boot. The labels signal is the published `versionId` in the client config, so the client refetches its locale when it changes. The Origin guard is one middleware in `packages/api/src/http/security.ts`. No new runtime dependency; no migration is expected.

## Decisions (developer 10-19-26: each as recommended; see "Rulings")

- **D-M2P3-1 Foreign `Origin` on REST (#753).** Recommended: B, one middleware on `/api/**` refusing any request whose `Origin` is present and not in `env.corsOrigins` (the REST CORS set: `CORS_ORIGINS` or the public origin, plus the dev origins in development, `env.ts:83-89`), cookie or bearer, with 403 `forbidden` before auth (Task 9). A missing `Origin` passes (native, curl, smoke): on REST a cookie request still needs `X-Requested-With` for any write, and a cross-site read gets no CORS grant. The WebSocket gate keeps its own set (public origin plus dev origins, `ws/server.ts:92-95`) and its stricter missing-Origin rule (bearer only; review c061: a socket has no CORS); `ws/server.ts` is not changed. Alternatives: A (no change, ruling on #723 stands; Task 9 dropped) or C (refuse only when `Authorization: Bearer` is present). Ruled B ([ruling on #753](https://github.com/BirchDesignLab/queryModule/issues/753#issuecomment-6280920711); #753 closed).
- **D-M2P3-2 "Replay excludes hidden".** Hiding (`result_visibility`, `resultHidden`) lands in M3 P2, so nothing can be hidden in M2 and the item cannot be tested yet. Recommended: ADR-0014 amends the spec 12.7 M2 row (as ADR-0012 did for M1) and moves this item to the M3 P2 gate with hide; Task 18 writes it. Alternative: build `result_visibility` and the replay filter in M2 P3 (a migration and critical work pulled forward from M3 P2).
- **D-M2P3-3 Change-password guesses (#46).** Recommended: a per-account limiter on wrong `currentPassword` (key `changePassword:<userId>`, 5 failures in 15 minutes, then 429 `rateLimited` on change-password only), with no account lockout, so a stolen session cannot lock its owner out of sign-in (Task 10). No audit row for a refused attempt or the block: spec 4.7 `passwordChanged` says "a failed change writes none", and the audit catalogue is frozen. Alternative: accept the IP limiter and record a ruling.
- **D-M2P3-4 Image config on a seeded deploy (CFG-4).** Today a seeded store ignores the image's site and mock files (logged "site config file ignored"), so `adminAudit: true` and the M2 mock changes reach a seeded host only through a database reset or a builder publish. Recommended: an ops command `config:import` that validates the image file, saves it as a draft and publishes it through `activate()` with the normal `configPublished` row (actor: a named admin), with `--dry-run` printing `diffConfig` lines first (Task 7); never an automatic merge at boot. The command runs in its own process, so the running app keeps its in-memory snapshot (`activate.ts:19-20`) until it restarts: the runbook is dry run, import, `docker compose restart app`. The store holds one draft per site, so the command refuses when a draft exists unless `--replace-draft` is passed. A live import is a publish: the developer approves it at the host step (D-M2P3-10). Alternatives: a builder Import action (Track B, larger); or document a reset step. Ask: is the live host's store seeded, and does the M2 promote need `config:import` to show the audit log there?
- **D-M2P3-5 Label-only publishes (CFG-1).** Recommended: in P3 (Task 8), `GET /api/v1/config` carries the published `versionId`; the client's existing config poll (`config-refresh.ts:60-75`) sees it change, refetches `["locale", locale]` and swaps the translator; `configHash` stays siteConfig only (CFG-3). No WebSocket change. Additive contract change with a master plan 8.4 row. Alternative: move to M3 P0 contracts.
- **D-M2P3-6 Watch and conditional items.** Recommended: no task for #748, T27 CV1, the #483 sticky watch and G-m4; move them to an M3 follow-up issue at the exit so #46 can close. The #645 watch items keep the ruling "fix when it recurs twice or a cause is found" (Track B plan).
- **D-M2P3-7 Shipped-only label keys endpoint (#46).** A new route is a contract change, and M2 contracts are frozen. Recommended: move to M3 P0 contracts. Alternative: a P3 contract PR in lane C.
- **D-M2P3-8 Lanes.** Recommended: three lanes, as P2: A (critical waves), C (gate and ops waves), B (web, Track B plan). Lanes A and C share no source file. Alternative: two lanes, lane C's waves after AW2 in lane A.
- **D-M2P3-9 Deferred boxes.** Recommended: at the exit, move the M3-deferred boxes listed in "Box audit" to the M3 phase parents and close #620, #623, #317 and #511.

## Global Constraints

- Runtime Node 24 LTS; TypeScript strict, no `any`; `packages/core` pure (no IO, clock or randomness).
- TDD for every task; the failing test is written and seen failing first; tell the implementer that TDD order is reviewed.
- Git: one wave, one branch `feat/m2-a-p3-wave-<k>` (lane C: `feat/m2-c-p3-wave-<k>`), one PR, squash merge. Never commit to `main`. Shas only from `git rev-parse` or `git merge-base` in the same step.
- Contract first (master plan 8): Task 8 is the only contract change (additive, its 8.4 row, `pnpm contracts:gen`, `pnpm client:gen`, oasdiff in the PR body). Any other task that finds it needs one stops and asks the manager.
- Audit (SEC-010 to SEC-013): every row through `d.audit.record(tx, event)` in a transaction; a failed audit write fails closed. Rows are never updated or deleted. Details hold identifiers and metadata only.
- Data: no query value, payload text, password or token in any log line, error or audit detail (spec 5.9). Every `/api` response keeps `Cache-Control: no-store`.
- Fixture policy unchanged (spec 5.4): no new fixtures; tests reuse the generator's scenarios and the seeded demo users.
- Migrations: none expected. `check-audit-migrations.ts` and `check-schema-writes.ts` stay green.
- Windows lanes: Git Bash first on PATH; `openTempDatabase`; spawn-heavy tests carry explicit timeouts; process tests `skipIf(win32)` and run in CI. Run the full e2e suite before a push, not only the specs touched.
- Docs and copy: American English; no em dashes; dates MM-DD-YY in prose, ISO in code and file names.
