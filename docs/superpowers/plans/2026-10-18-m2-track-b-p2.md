## Global Constraints

- TypeScript strict; no `any`. Every user-facing string is a message key in `packages/config/locales/en.json` (NFR-001), with the locale-keys test. American English in copy.
- Payloads, typed values and audit rows are regulated data on the client (spec 6.7): memory only (no storage, no persister, no service worker); cleared on logout, 401 or user change; never in logs, analytics or URLs the app builds for navigation. The export is a GET whose query string carries ids, a type name and epoch numbers only (the contract); the file goes straight to a download, never into app state beyond the click.
- Admin pages render only for `features.adminAudit` and the `admin` role (an implementer sees no audit entry: its routes are 403); the rail item follows the same rule.
- Announcements: polite and coalesced (spec 6.6); a page load announces the row count, never row content; errors name the field ("Window can span at most 31 days").
- Focus: paging and filtering keep focus on the control used; a new page never moves focus to the table unless the user asked (spec 6.6). Every control is reachable by keyboard in order; the table is a real `<table>` with a caption and column headers.
- Severity and status never by color alone (spec 4.5, 6.2).
- Design: the visual system and the approved mockup are the target; tokens only (no literal colors); the `shell.css.test.ts` layout constants (1024, 864, 720) for container queries.
- Windows lane: `VITEST_MAX_WORKERS=3`; explicit `findBy` timeouts in admin tests that load under full-suite load (#610 pattern); e2e with `E2E_PORT=3200 pnpm e2e <spec> --project=chromium`.
