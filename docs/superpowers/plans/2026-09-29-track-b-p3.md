## Global Constraints

- Runtime: Node 24 LTS (ADR-0001); TypeScript strict; no `any`.
- TDD for every task: failing test first, seen failing, then implementation (tell the implementer TDD order is reviewed).
- One wave, one branch `feat/b-p3-wave-<k>`, one PR, squash merge. Never commit to `main`; ask before every push.
- Contract first: this plan changes no contract file. `POST /api/v1/queries` (P2 D-A3) is consumed as generated in `packages/client/src/api/generated/openapi-types.ts`.
- Core is pure: no IO, clock or randomness; `now` is passed in.
- Forms and the terminal render only from `FormState` and the site config; no per-query-type UI code (BR-001).
- Messages: every user-facing string is a locale key; errors are `{ key, params }`; params never carry typed values except `terminal.unknownCommand { code }` and `terminal.unknownField { name }`, which are shown to the user only and never logged (spec 4.4, #296).
- Regulated data on the client: drafts, terminal text, config, submit bodies and acknowledgments never reach `localStorage`, `sessionStorage`, IndexedDB or a persister; every new store registers with `ResetController` and is tested reset on logout, 401 and user change (spec 6.7).
- State-changing requests carry `X-Requested-With: querymodule` (the API client adds it); every request `cache: "no-store"`.
- Announcements: one announcer; polite for ack, validation counts, terminal errors and connection changes; assertive only for `critical` severity (none in M1). Never add `role="alert"` anywhere else (spec 6.6; P2 B4 critic).
- Accessibility: every Playwright scenario runs axe and fails on serious or critical violations and on any CSP violation; submit uses `aria-disabled`, never `disabled`; incoming events never move focus (spec 6.2, 6.6, 10.6).
- Keyboard: single keys are inert in text inputs and in `[data-terminal]`; Ctrl+A, C, V, X, Z, Y are never bound (spec 6.4).
- Fixture policy (spec 5.4): plates `ZZ-####`, synthetic names, DOBs in 1901; test emails on `.test`; trigger inputs `ABC123`, `TIMEOUT`, `FAIL1`, `WANTED` are exempt.
- e2e on Windows: `pnpm e2e` needs `E2E_USER_EMAIL=smoke@example.test` and the password derived as in `.github/workflows/ci.yml` step 12 (never print it); wait for the quick-access bar (`Quick access` navigation) before sending keys (after Task 12 the "Query type" select may be absent); press Enter from a non-text control when testing a non-native submit path; use sentinel announcements, never fixed sleeps.
- Docs: no em dashes; dates MM-DD-YY in prose.
