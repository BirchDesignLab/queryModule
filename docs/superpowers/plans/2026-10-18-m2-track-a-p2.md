**Goal:** Make the audit trail readable and complete for M2: admins read and export the audit log (cursor paged, audited as `auditViewed` and `auditExported`) and open any request with its payloads (audited as `adminViewed`); a 60 s sweeper owns session expiry with its `sessionRevoked` row and prunes `event_log` hourly; the publish change note is stored and shown with the publisher's name; the 202 reports `Server-Timing` and the client's ack receipt is recorded as a metric; story A9 gets its tagged test. Core lane: `config:validate` resolves mapping paths against mock payloads and gains `--diff <tag>`; bearer REST and WebSocket tests land.

**Architecture:** The admin audit reader and its routes live in `packages/api/src/audit/` (critical: they write audit rows); the admin query read lives beside the owner's read in `packages/api/src/queries/` (critical: it decrypts payloads). Both mount behind `adminGuard(d, "adminAudit", ["admin"])` (`admin/access.ts`). The sweeper is `packages/api/src/dispatch/sweeper.ts` (critical), the periodic counterpart of the startup sweep (`dispatch/sweep.ts`), started by `startup.ts` and stopped by the drain. The note needs one migration (`0011`). Core gains `packages/core/src/response/check-paths.ts` (pure), wired into `scripts/ci/config-files.ts`. No new runtime dependency.

**Tech Stack:** Node 24 LTS, TypeScript strict, `hono`, `drizzle-orm`, `@libsql/client`, `zod` v4, `ws`, `vitest` (fake timers), `fast-check`.

**Spec:** `docs/superpowers/specs/2026-09-25-query-module-2-design-v2.md`: 4.1 (`auth.session`, `retention`), 4.5 (mapping paths), 4.7 (audit catalogue: `auditViewed`, `auditExported`, `adminViewed`, `sessionRevoked`), 5.1 (admin routes), 5.2 (sweeper, access policy), 5.5 (retention, `purged`), 5.6 (session limits, auth audit), 7 (`config:validate`), 10.2 (A9), 10.3, 10.7 (bearer), 11 (NFR-004 split), 12.3 (M2 P2 row). ## Global Constraints

- Runtime Node 24 LTS; TypeScript strict, no `any`; `packages/core` pure (no IO, clock or randomness).
- TDD for every task; the failing test is written and seen failing first; tell the implementer that TDD order is reviewed.
- Git: one wave, one branch `feat/m2-a-p2-wave-<k>` (lane C: `feat/m2-c-p2-wave-<k>`), one PR, squash merge. Never commit to `main`. Shas only from `git rev-parse` or `git merge-base` in the same step.
- Contract first (master plan 8): Tasks 1 and 2 are the only contract changes (their own PR, master plan 8.4 rows, `pnpm contracts:gen` and `pnpm client:gen`, oasdiff in the PR body), except the named `status: "planned"` -> `"live"` flip in each of Tasks 3, 4 and 5 (each with its 8.4 row, as #622 did for `getQuery`; `route-matrix.test.ts` requires `CONTRACT_ONLY` to equal the planned routes, so the flip and the mount land together). Any other task that finds it needs a contract change stops and asks the manager.
- Audit (SEC-010 to SEC-013): every row through `d.audit.record(tx, event)` in a transaction; a failed audit write fails the request closed (500 `internal`, nothing returned that the row was to cover). Rows are never updated or deleted (triggers `0001`). Details hold identifiers and metadata only: no query values, payload text, typed free text (the publish note never enters an audit row) or error messages.
- Access: admin routes answer 404 `notFound` when `adminAudit` is off (to every caller), 401 with no session, 403 `passwordChangeRequired`, 403 `forbidden` for any role but `admin` (`adminGuard`, ADR-0011 item 6). The owner's routes keep 404 for anyone else (spec 5.2).
- Data: decrypted values and payloads exist only in the admin query response body; never in logs, errors, events, metrics or audit details (spec 5.9). Logs carry ids, counts and error classes only. Every `/api` response keeps `Cache-Control: no-store`.
- Fixture policy unchanged (spec 5.4): no new fixtures; tests reuse the generator's scenarios (`ZZ-0001`, `ABC123`, `FAIL1`, `TIMEOUT`, `WANTED`, `MISSING`, `ZZSTOLEN1`) and the seeded demo users.
- Migrations: exactly one, `0011` (Task 10). `scripts/ci/check-audit-migrations.ts` and `check-schema-writes.ts` stay green.
- Windows lanes: Git Bash first on PATH; `openTempDatabase`; win32 teardown best-effort; spawn-heavy tests carry explicit timeouts; process tests `skipIf(win32)` and run in CI.
- Docs and copy: American English; no em dashes; dates MM-DD-YY in prose, ISO in code and file names.
