## Global Constraints

- Runtime Node 24 LTS; TypeScript strict, no `any`. Core pure.
- TDD for every task; the failing test is written and seen failing before code. Tell the implementer up front that TDD order is reviewed.
- Git: one wave, one branch `feat/m2-a-p05-wave-<k>`, one PR, squash merge. Never commit to `main`.
- Contract first: this plan changes no contract file (`sourceStatus`, `welcome.latestSeq`, `sourceResponded`, `interrupted`, `unavailable` are frozen since M0 P0; `resultHidden` and `resync` come from M2 P0). A task that finds it needs one stops and asks the manager (master plan 8).
- Persistence: timestamps INTEGER epoch ms UTC; ids UUIDv7; durations from the monotonic clock.
- Audit: every write through `AuditService.record(tx, event)` inside the transaction that makes the change; a failed audit write rolls it back (fail closed).
- Status is write-once from `pending` (trigger): every T2 update carries `WHERE result_id = ? AND status = 'pending'`; zero changed rows means nothing else is written.
- Events are reference-only (ids and status, never payloads or values); `EventBus.publish` runs only after the `event_log` row commits.
- Logs: no field values, payloads, adapter error text, secrets, key material, DEKs or tokens (spec 5.9); adapter failures log the error class and ids only.
- Fixture policy (spec 5.4): plates `ZZ-####`, VINs failing the ISO 3779 check digit, DOBs in 1901, synthetic names (Testerson, Sampleworth), addresses on Example Ave; trigger inputs in `when` are exempt.
- Config snapshots: dispatch reads the config snapshot pinned at prepare, never `d.config.current()` at dispatch time. Drain and sweep read the live holder.
- Migrations: `event_log` is `0010` (M2 P0 Task 1 adds `0009`, `document_hash`, and merges before AW2); any other migration takes the next free number at branch time; if numbers collide, the later PR renumbers (`drizzle-kit` regenerates `meta/`); `check-audit-migrations` must pass.
- Timers: dispatcher, deadlines and latency take injected `Timers` and `MonotonicClock`; no real sleeps in unit tests.
- Windows lane: `openTempDatabase`; win32 teardown best-effort; Git Bash first on PATH; spawn-heavy tests carry explicit timeouts; process tests `skipIf(win32)` and run in CI.
- CI and deploy facts to keep: no `cancel-in-progress` on `main`; `deploy/compose.yml` keeps `autoheal: "False"` and `stop_grace_period: 30s`; `restore-test.sh` keeps per-file secret mounts.

### Task 1: Core: fixture policy check for mock payloads (#529)

**Files:** Create `packages/core/src/config/fixture-policy.ts`, `fixture-policy.test.ts`. Modify `packages/core/src/config/index.ts`.
**Interfaces:**

```ts
export interface FixtureDiagnostic { pointer: string; key: "fixture.realPlate" | "fixture.validVin" | "fixture.plausibleDob" | "fixture.nonSyntheticName" | "fixture.nonExampleAddress" | "fixture.unknownKey" | "fixture.freeTextDigits" }
/** Allowlist of payload keys by kind (spec 5.4); listed in docs/site-config.md. Keys are normalised before lookup: lower-cased, "_" and "-" removed. */
export const FIXTURE_LEAF_KEYS: { plate: readonly string[]; vin: readonly string[]; dob: readonly string[]; name: readonly string[]; address: readonly string[]; status: readonly string[]; freeText: readonly string[]; other: readonly string[] };
export const SYNTHETIC_NAMES: ReadonlySet<string>;   // upper-case: TESTERSON, SAMPLEWORTH, SAMPLE, TEST, EXAMPLESON, ...
/** Walks every respond and default payload, recursing into objects and arrays (never `when`; trigger inputs are exempt), and reports each violation with its JSON pointer. */
export function checkFixturePolicy(file: MockFile): FixtureDiagnostic[];
export function vinCheckDigitValid(vin: string): boolean;   // ISO 3779 position 9; a VIN must FAIL it to be fictitious
export function normaliseFixtureKey(key: string): string;
```

Rules (spec 5.4, 10.8). Payloads are free-form (`SourcePayloadSchema = z.record(z.string(), z.unknown())`, `contracts/mock-file.ts:9`) and the M2 P0.5 mock editor lets admins type keys, so the policy is an **allowlist**, not a deny list (adversarial review 10-05-26: `ownerName`, `surname`, `registeredOwner`, `dateOfBirth` and `remarks: "JOHN SMITH DOB 04/12/1985"` all passed a key deny list):
- Every object key, at any depth, normalised with `normaliseFixtureKey`, must be in one of the `FIXTURE_LEAF_KEYS` lists, else `fixture.unknownKey` (this also stops data hidden in object keys).
- `plate` keys: values match `^ZZ-\d{4}$`. `vin`: 17 characters failing `vinCheckDigitValid`. `dob`: ISO dates in 1901. `name` (for example `last`, `first`, `middle`, `name`, `lastname`, `firstname`, `surname`, `ownername`, `registeredowner`): every word in `SYNTHETIC_NAMES`. `address` (`address`, `street`, `addressline1`): ends with `Example Ave`. Non-string values under these keys are violations.
- `freeText` keys (for example `remarks`, `note`, `caution`): canned text with no digits (`fixture.freeTextDigits`).
- `status` and `other` keys (for example `status`, `make`, `model`, `color`, `year`, `type`, `warrant`, `agency`): values are free but `other` strings may not contain a run of 4 or more digits unless they are a `year` in 1901 to 1999 (the report justifies each `other` key).
Before fixing the lists, the implementer runs the check over the shipped mock files (which include the M1 additions DL, PRO `ZZSTOLEN1`, WNT `MISSING`) and builds the allowlist from the keys they use; the report lists every key and its kind.
