## Global Constraints

- Runtime: Node 24 LTS (ADR-0001); TypeScript strict; no `any`.
- Workspace: `pnpm install --frozen-lockfile`. No new runtime dependency; an addition would be its own `chore/deps-<name>` PR.
- Method: TDD for every task; the failing test is written and seen failing before code (master plan 6.3 step 12). Tell the implementer up front that TDD order is reviewed.
- Git: one wave, one branch `feat/a-p3-wave-<k>`, one PR, squash merge. Never commit to `main`. Ask before every push.
- Contract first: this plan changes no contract file (`submitQuery` already declares 503 `unavailable`; `sourceStatus`, `welcome.latestSeq`, `sourceResponded` and `interrupted` are frozen since P0). A task that finds it needs one stops and opens a `contract` issue (master plan 8). D-A10 option (b) would add one.
- Core is pure: no IO, clock or randomness in `packages/core`.
- Persistence: timestamps INTEGER epoch ms UTC; ids UUIDv7 text; durations from the monotonic clock (spec 4.7, 5.5).
- Audit: every audit write goes through `AuditService.record(tx, event)` inside the transaction that makes the change; a failed audit write rolls it back (spec 5.2, fail closed). `details` hold identifiers, metadata and `role: "type"` values only.
- Status is write-once from `pending` (spec 5.5 trigger): every T2 update carries `WHERE result_id = ? AND status = 'pending'`; zero changed rows means nothing else is written.
- Events are reference-only: `sourceStatus` carries ids and status, never payloads or values (spec 4.7); `EventBus.publish` runs only after the `event_log` row commits.
- Logs: no field values, payloads, adapter error text, secrets, key material, DEKs or tokens in any line (spec 5.9). Adapter failures log the error class and ids only.
- Fixture policy (spec 5.4): plates `ZZ-####`, VINs failing the ISO 3779 check digit, DOBs in 1901, synthetic names (Testerson, Sampleworth), addresses on Example Ave. Trigger inputs (`ABC123`, `TIMEOUT`, `FAIL1`, `WANTED`) are exempt.
- Timers: dispatcher, deadlines and backoff take injected `Timers` and `MonotonicClock` so tests use Vitest fake timers; no real sleeps in unit tests.
- Windows lane: API tests use `openTempDatabase`; win32 teardown is best-effort; Git Bash first on PATH; spawn-heavy tests carry explicit timeouts (A3 #312).
- CI and deploy facts to keep: no `cancel-in-progress` on `main`; `deploy/compose.yml` keeps `autoheal: "False"` and `stop_grace_period: 30s`; `restore-test.sh` keeps per-file secret mounts (#249, #237).
- Host access: none from a session. Host steps are developer-run with exact commands.
- Docs: no em dashes; dates MM-DD-YY in prose, ISO in code and file names.

**Files:** Create `packages/core/src/config/fixture-policy.ts`, `fixture-policy.test.ts`. Modify `packages/core/src/config/index.ts`.
**Interfaces:**

```ts
export interface FixtureDiagnostic { pointer: string; key: "fixture.realPlate" | "fixture.validVin" | "fixture.plausibleDob" | "fixture.nonSyntheticName" | "fixture.nonExampleAddress" }
/** Leaf keys read as record fields (spec 5.4); listed in docs/site-config.md. Matched case-insensitively. */
export const FIXTURE_LEAF_KEYS: { plate: readonly string[]; vin: readonly string[]; dob: readonly string[]; name: readonly string[]; address: readonly string[] };
export const SYNTHETIC_NAMES: ReadonlySet<string>;            // upper-case: TESTERSON, SAMPLEWORTH, SAMPLE, TEST, EXAMPLESON, ...
/** Walks every respond and default payload (never `when`, trigger inputs are exempt) and reports each violating leaf with its JSON pointer. */
export function checkFixturePolicy(file: MockFile): FixtureDiagnostic[];
```
