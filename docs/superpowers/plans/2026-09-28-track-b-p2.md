- Core is pure: no IO, clock or randomness; `now` is passed in.
- Forms render only from `FormState`; no per-query-type UI code (BR-001, spec 6.2).
- Messages: every user-facing string is a locale key; errors are `{ key, params }`; params never carry typed values except where spec 4.4 names them (`terminal.unknownCommand { code }`, `terminal.unknownField { name }`).
- Regulated data on the client: drafts, config and query data never reach `localStorage`, `sessionStorage`, IndexedDB or a persister; reset on logout, 401 or user change (spec 6.7).
- State-changing requests carry `X-Requested-With: querymodule`; every request `cache: "no-store"` (spec 5.9).
- Accessibility: every Playwright scenario runs axe and fails on serious or critical violations and on any CSP violation (spec 9.3 step 12, 10.6); submit uses `aria-disabled`, never `disabled` (spec 6.2).
- Keyboard: single keys are inert in text inputs; Ctrl+A, C, V, X, Z, Y are never bound (spec 6.4).
- Fixture policy (spec 5.4): plates `ZZ-####`, synthetic names, DOBs in 1901; test emails on `.test`.
- Docs: no em dashes; dates MM-DD-YY in prose.

```ts
/** Codes a literal on this field is checked against: all codes (conditions) or enabled codes (defaults, setDefault, presets). Undefined for non-picklist fields. */
export function literalCodes(picklists: readonly Picklist[], field: FieldDef, scope: "all" | "enabled"): readonly string[] | undefined;
/** Spec 4.2: literals are canonicalised at load with the target field's dataType. Returns the errors, unlike the compile path. */
export function canonicaliseLiteral(field: FieldDef, literal: Literal, o: { now: number; codes?: readonly string[] }): CanonResult;
/**
 * A stable key for a condition: literals canonicalised (a failing literal kept as {"raw": value}),
 * in/notIn values sorted and deduplicated, all/any children sorted and deduplicated, object keys sorted.
 * Two conditions with equal keys hold on exactly the same effective values.
 */
export function canonicalCondition(condition: Condition, fields: ReadonlyMap<string, FieldDef>, picklists: readonly Picklist[], now: number): string;
```

`picklistFilter` narrowing is not applied to literals (a literal is checked against the field's own picklist, as `compile.ts` does today).

```ts
// packages/core/src/terminal/tokenize.ts
import { FIELD_KEY_PATTERN } from "../contracts/primitives";
import { findQueryType } from "../rules/compile";
import type { TerminalConfig, TokenizeResult } from "./types";

const fieldOf = (p: string | { field: string; rest?: boolean }) => (typeof p === "string" ? p : p.field);
const isRest = (p: string | { field: string; rest?: boolean } | undefined) => typeof p === "object" && p.rest === true;

/** Spec 4.4. Pure; returns every value it could read and every error it found. */
export function tokenize(config: TerminalConfig, input: string): TokenizeResult {
  const out: TokenizeResult = { userValues: {}, positionedKeys: [], presetKeys: [], namedKeys: [], errors: [] };
  const text = input.trim();
  if (text === "") return { ...out, errors: [{ key: "terminal.emptyInput" }] };
  const d = config.terminal.delimiter;
  const cut = text.indexOf(d);
  const code = (cut === -1 ? text : text.slice(0, cut)).trim();
  const cmd = config.commands.find((c) => c.code.toLowerCase() === code.toLowerCase());
  if (cmd === undefined) {
    const error = cut === -1
      ? { key: "terminal.missingDelimiter", params: { length: text.length } }
      : { key: "terminal.unknownCommand", params: { code } };
    return { ...out, errors: [error] };
  }
  out.commandCode = cmd.code;
  out.queryType = cmd.queryType;
  const qt = findQueryType(config, cmd.queryType);
  const labelOf = new Map((qt?.fields ?? []).map((f) => [f.key, f.labelKey]));
  const byLower = new Map((qt?.fields ?? []).map((f) => [f.key.toLowerCase(), f.key]));
  for (const [k, v] of Object.entries(cmd.presets ?? {})) { out.userValues[k] = String(v); out.presetKeys.push(k); }
  if (cut === -1) return out;

  let remaining: string | null = text.slice(cut + d.length);
  let pos = 0;          // next CommandDef position
  let tokenNo = 0;      // 1-based value token number
  let seenNamed = false;
  let nonEmptyPositional = 0;
  const taken = (k: string) => out.presetKeys.includes(k) || out.positionedKeys.includes(k) || out.namedKeys.includes(k);
  while (remaining !== null) {
    const p = cmd.positions[pos];
    if (!seenNamed && isRest(p)) {                   // rest: the remainder verbatim, named tokens no longer read
      tokenNo += 1;
      const value = remaining.trim();
      const key = fieldOf(p!);
      out.userValues[key] = value; out.positionedKeys.push(key); pos += 1;
      if (value !== "") nonEmptyPositional += 1;
      break;
    }
    const k = remaining.indexOf(d);
    const token = k === -1 ? remaining : remaining.slice(0, k);
    remaining = k === -1 ? null : remaining.slice(k + d.length);
    if (token.trim() === "" && (remaining === null || remaining.split(d).every((x) => x.trim() === ""))) break; // trailing empties
    tokenNo += 1;
    const eq = token.indexOf("=");
    if (eq > 0) {
      const name = token.slice(0, eq).trim();
      const key = byLower.get(name.toLowerCase());
      if (key !== undefined) {
        if (taken(key)) out.errors.push({ key: "terminal.duplicateField", params: { field: key, labelKey: labelOf.get(key) ?? key } });
        else { out.userValues[key] = token.slice(eq + 1).trim(); out.namedKeys.push(key); }
        seenNamed = true;
        continue;
      }
      if (seenNamed && FIELD_KEY_PATTERN.test(name)) { out.errors.push({ key: "terminal.unknownField", params: { name } }); continue; }
    }
    if (seenNamed) { out.errors.push({ key: "terminal.positionalAfterNamed", params: { position: tokenNo } }); continue; }
    const value = token.trim();
    if (value !== "") nonEmptyPositional += 1;
    if (pos >= cmd.positions.length) continue;       // counted for tooManyPositions below
    const key = fieldOf(cmd.positions[pos]!);
    pos += 1;
    out.userValues[key] = value; out.positionedKeys.push(key);
  }
  if (nonEmptyPositional > cmd.positions.length) {
    out.errors.push({ key: "terminal.tooManyPositions", params: { expected: cmd.positions.length, got: nonEmptyPositional } });
  }
  return out;
}
```

Note: `nonEmptyPositional` counts the extra tokens too, so `got` is the number of non-empty positional tokens typed (spec 4.4 table).

## Open questions from the requirements (spec "Open Questions (TBD)")

Listed for the developer; this plan decides none of them. Design v2 section 11 already records a decision for the first two, and P1 built on the first; they stay open in the requirements document until the developer closes them there.

1. **Rule condition language.**
   - (a) Structured JSON conditions (`{ field, op, value }`, `all`/`any`/`not`, `$default`), no expression strings, no eval: design v2 4.2 and 11; the P1 rules engine and P0 config schema implement it.
   - (b) An expression string syntax like the Appendix B example (`state != default(state)`), parsed by core into the same tree.
   - (c) Both: JSON is canonical; a string form is accepted in site files as sugar and `config:migrate` rewrites it to JSON.
   - Recommendation: (a) now; revisit (c) only if site developers ask for terser rules, with a parser in core and no eval. A change would be a config contract change.
2. **Values carry over between form and terminal (FR-056).**
   - (a) Yes, both ways: the draft is user values, the terminal a derived view, unpositioned values kept with "n fields not shown" (design v2 4.4, 6.7, 11); Tasks 6, 7 and 9 build it.
   - (b) Terminal to form only; switching to the terminal starts empty.
   - (c) No carry-over; each mode has its own draft.
   - Recommendation: (a). It is what A5's property test proves, and it loses no typed value in either direction.
3. **Scan auto-submit (FR-074, Phase 3, stories C3 and C4).**
   - (a) Confirm first: a scan fills the fields and the user submits.
   - (b) Auto-submit when the scan fills every required field.
   - (c) A per-site setting (for example `scan.autoSubmit`, default false), optionally per query type.
   - Recommendation: (c) with default false, so the default behaves as (a) and an agency can opt in; design it with the Phase 3 scan work (design v2 11 keeps it TBD). Nothing in M1 depends on it.
