# 0001 Node 24 LTS as the runtime

## Context

Spec v2 section 3 pins Node 22 LTS. By 09-26 Node 22 is in maintenance and Node 24 is the active LTS. `CLAUDE.md` sets the dependency policy as newest stable with no known advisories. Section 8 already pins the runtime image to `node:<lts>-alpine` at the same major as `.nvmrc`, so the choice lives in one place. No code exists yet, so the change costs nothing now and a migration later.

## Options

1. Node 22 LTS: matches spec v2 as written; maintenance-only security fixes; falls out of support before M4 is likely done.
2. Node 24 LTS: active LTS through the project; matches the newest-stable rule; Expo SDK and `@libsql/client` native bindings must be confirmed on 24 at P0 (both publish for current LTS).

## Decision

Node 24 LTS. `.nvmrc` reads `24`, root `package.json` `engines.node` is `>=24 <25`, the Dockerfile runtime stage is `node:24-alpine` pinned by digest, CI uses `actions/setup-node` with `node-version-file: .nvmrc`.

## Consequences

- Spec v2 section 3 now reads "Node 24 LTS" and cites this ADR. Section 8 needs no change.
- Master plan machine setup installs Node 24 on both machines.
- P0 contracts plan adds a check that `expo export` and `@libsql/client` load on Node 24; failure of either reopens this ADR.
- Follow-up issue: none until P0 opens the workspace.
