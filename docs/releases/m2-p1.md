# M2 P1 Feed

Date: 10-14-26

M2 P1 shows the answers. A query's results appear inside its request as result cards (mapped summary and detail, tables, keyword marks, a severity badge, a generic dump when no card is set up), a client that was offline catches up by replay, and the requests list survives a reload. The cards and keywords are configured from the admin builder. P1 is not a milestone exit, so there is no milestone tag; the demo is a decision point at this gate (ADR-0012).

## Config changes for site developers
Config schema stays at v1. The text below is the first draft's account, written at 08278e2: `pnpm config:validate --resolved` on `default.json` and `example-ok.json` differed from the M1 files ([`m1/default.resolved.txt`](m1/default.resolved.txt), [`m1/example-ok.resolved.txt`](m1/example-ok.resolved.txt)) in one key only, `responseMappings`; since #669 `keywords` differs as well (see Since the first draft). The five shipped cards (`veh-summary`, `per-summary`, `pro-summary`, `wnt-summary`, `dl-summary`) went from one or two `status`-and-identifier rows to summary and detail rows (the warrants table on `wnt-summary`). Everything else is identical, and the status lines read as below at the first draft (since #675 both read `0 warnings`, because the six deliberate form-only fields are flagged `formOnly`):

```
ok packages/config/sites/default.json (6 warnings)
ok packages/config/sites/example-ok.json (7 warnings)
```

A site file that extends `default` inherits the new cards; an overlay that restates `responseMappings` replaces the list by entry `id` as before, so a site that wants the old two-row cards restates them.

What changed for a site developer or admin (reference: [site-config.md](../site-config.md)):

- Result cards: `responseMappings` are now applied. The browser picks the best mapping per part (`when` +4, source +2, persona +1, ties to config order), renders its elements from the payload with the path language (dot, `[n]`, `[*]`, `["key"]`), the formats and tables, and falls back to a generic dump when no mapping qualifies. A mapping's `when` reads the values the server planned for that part.
- Keywords and severity: `keywords` and `keywordSeverityStyles` now drive highlighting and the severity badge (`assessResult` scans every string leaf of the payload, independent of the card). Shipped severity styles are at least 7:1 in every theme mode (info raised, red-shift critical raised).
- Default site: one synthetic driver's license record (`ZZDLTEST`, state source) in the default mock, and `licenseNumber` joined the fixture policy's `other` leaves. The fixture policy now counts digit runs across every non-alphanumeric separator in `other` and `status` leaves, and rejects exponent-form numbers (#636, #638). The default cards for all five query types now carry summary and detail rows, with a warrants table on the wanted card (BW3, #602).
- Admin builder: a Result cards group (card editor with rows, "which card wins" table, a card preview that renders the production card with the draft's cards, keywords and styles), a Keywords and severity editor (keywords, exceptions, style pickers, contrast per theme with a "(under 7:1)" hint, live sample), and "Try a match" in the mock editor (#565). Review and publish lists the card and keyword changes by pointer and card id. Known limit: a config refresh does not refetch the locale bundle, so a label added in the builder reaches a tab already open only after it reloads.
- Mock scenarios the demo and the e2e use, and the result-card and builder click paths: [demo.md](../demo.md).

## API and WebSocket contract changes
Reference: [api.md](../api.md).

- `api-breaking` (#611, #576): the read part of the contract-only routes `GET /queries`, `GET /queries/{correlationId}` and `GET /admin/queries/{correlationId}` replaced `skippedReason` with `skipReasons` (a list of `{ key, params }`, keys and params only, never a value). oasdiff reports it as a response property removal (ERR). Nothing served these routes before P1, so no client could depend on the field. The gate run's oasdiff (v1.32.1, the CI image pinned by digest; base `fe47c0f`, the M2 P0.5 release note, against `main` at 08278e2, after the rename map) printed:

```
3 changes: 3 error, 0 warning, 0 info
error	[response-required-property-removed] in API GET /api/v1/admin/queries/{correlationId}
		removed the required property `parts/items/skippedReason` from the response with the `200` status
error	[response-required-property-removed] in API GET /api/v1/queries
		removed the required property `requests/items/parts/items/skippedReason` from the response with the `200` status
error	[response-required-property-removed] in API GET /api/v1/queries/{correlationId}
		removed the required property `parts/items/skippedReason` from the response with the `200` status
```

  Nothing else in the API contract changed in a breaking way: no warning or info line.
- `POST /queries` 202: each part also carries `origin` (`primary` or `alsoRun`), `parentPartId` and `skipReasons` (additive). A replayed idempotency key rebuilds them from the stored request.
- `GET /api/v1/queries` and `GET /api/v1/queries/{correlationId}` are served (#589, #618): the caller's own requests, newest first with a cursor; one request with its decrypted values and, for each `returned` source, its payload. Another user's request, an admin's view of it, an unknown id and a malformed id all answer `404 notFound`. The status cell in the route table still reads `planned` until the contract wave (#622).
- WebSocket replay (#590, #621): `hello { lastSeq }` is answered by `welcome`, then the owner's `event_log` rows after `lastSeq` (at most 500, at most 24 hours old) or one `resync` (`tooOld`, `tooMany`, `unknownCursor`). `resync` is live; `resultHidden` is still planned (M3 P2); `ackReceipt` is accepted and ignored (the metric and `Server-Timing` are M2 P2).
- Smoke step 4 now checks the returned payload over HTTP (#592).

## Known limits
- Mock sources only. Nothing reaches a real state or national system, and the prototype holds no real CJIS data.
- No hide: delete from view and `resultHidden` are M3 P2. The list and detail routes exclude nothing until then.
- No Retry button on a failed or timed-out source (spec 5.7 work).
- The generic dump has no size or depth cap.
- `config:validate` does not resolve mapping paths against the mock payloads (M2 P2); the builder warns per row.
- `ackReceipt` metric and the 202 `Server-Timing` header are M2 P2.
- A bad stored event row closes the socket 1011 on every reconnect (#620); fixed with the M3 per-type mapper.
- The status cells for the two read routes in the `api.md` table still read `planned` (#622).
- Follow-ups: #623 (read mapper leftovers), #574, #572, #558, #610, #645 (test flakes). #647 closed in #657.
