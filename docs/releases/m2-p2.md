# M2 P2 Audit

Date: 10-19-26

M2 P2 makes the audit trail readable and complete. An admin reads the audit log in the admin console (filters, cursor paging, an NDJSON export) and opens any request read-only from it, and each of those reads is itself audited before anything is returned. A sweeper ends sessions at their live limits with an audit row and prunes the replay log. A config publish can carry a short note, shown in the history with the publisher's name. The 202 reports its acknowledgment time, and the client's receipt of it is logged as a metric. The terminal can sit beside the results. P2 is not a milestone exit, so there is no milestone tag; promoting this build to the demo host is the developer's call (see Gate).

What changed for a site developer or admin (reference: [site-config.md](../site-config.md)):

- `features.adminAudit` gates the audit log, its export and the admin request view (admin role only). It is on in the shipped sites; a site that turns it off gets `404` on those routes and no Audit log entry in the console.
- Session limits: `auth.session.absoluteMinutes` may not exceed 10080 (7 days, `config.sessionCeilingExceeded`), and `idleMinutes` may not exceed `absoluteMinutes` (`config.sessionIdleOverAbsolute`). No shipped config is affected.
- `config:validate` warns `config.mappingPathUnresolved` when a result-card path resolves in no mock answer of its source and query type (warnings never fail the build), and `config:validate --diff <tag>` prints what changed in each site file since a tag or sha.
- Publish: the dialog takes an optional note (up to 200 characters, one line); History shows each version's note and the publisher's name. The note is never written to the audit log.

## Upgrade impact

- Migration `0011` adds `site_config_version.note` and recreates the frozen-row trigger with one more condition: a published or superseded version's note never changes. Nothing else in the schema changes, and no audit trigger is touched.
- Better Auth's own session expiry is now the 7-day ceiling plus one day. A session signed in before the upgrade keeps the expiry it was stored with; the sweeper and the live limits end it first either way.
- The sweeper starts with the server and stops in the drain before the database closes. After the upgrade its first ticks expire the sessions already past the live limits (at most 500 a minute), each with a `sessionRevoked` row.

## API and WebSocket contract changes

All additive (oasdiff info only); every change has its master plan 8.4 row.

- `GET /api/v1/admin/audit` (cursor paged, newest first, window at most 31 days), `GET /api/v1/admin/audit/export` (NDJSON, at most 100,000 rows; more answers `400 validationFailed` with `audit.exportTooLarge`), and `GET /api/v1/admin/queries/{correlationId}` are live behind `adminAudit`, admin role only. Reference: [api.md](../api.md).
- Every 202 from `POST /api/v1/queries`, a replay included, carries `Server-Timing: ack;dur=<ms>;desc="receipt to commit"`, measured from request receipt. A request's `submittedAt` stays the audited admission time on the wall clock.
- `GET /api/v1/admin/config/versions` and `GET /api/v1/admin/config` serve each version's `note` and `publishedByName`.
- WebSocket: `ackReceipt` is recorded as a metric (one log line per owned request, not audit). A socket that sends more than 120 client frames in a minute is closed with 4029 (server-local; reconnect as for any close but 4001).

## Audit

- `auditViewed` (each audit page), `auditExported` (each export, with the row count offered) and `adminViewed` (each admin request view) commit before anything is returned; an audit write failure answers `500` with nothing in the body.
- `sessionRevoked` with reason `expired` and the system actor, written by the sweeper for each session it ends.
- Story A9 (`packages/api/test/audit/query-audit.a9.test.ts`) checks the query audit rows field by field, and reads them back through the admin audit route.
- Rows are never updated or deleted; the publish note and every payload stay out of audit details.

## Known limits

- Mock sources only. Nothing reaches a real state or national system, and the prototype holds no real CJIS data.
- `includeHidden` on the admin request view is recorded and has no effect until hide lands in M3 P2; every result reads `hidden: false`.
- The export is capped at 100,000 rows per call; narrow the window for more.
- `ackReceipt` counts once per correlation id per process; a restart can count a receipt again.
- The NFR-004 figures above come from a local run on one machine, not the demo host.
